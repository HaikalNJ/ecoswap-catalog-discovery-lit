# شرح مشروع Catalog & Discovery

## ما هو الجزء الذي أنجزناه؟

هذا المشروع يمثل جزء **Catalog & Discovery** من متجر EcoSwap للمنتجات
المستعملة. مسؤوليته عرض المنتجات ومساعدة المستخدم في إيجاد المنتج المناسب.

يحتوي على أربع وظائف مطلوبة في ورقة المشروع:

1. الصفحة الرئيسية.
2. قائمة المنتجات.
3. البحث والفلاتر.
4. صفحة تفاصيل المنتج.

## ما هي Lit؟

Lit هي مكتبة JavaScript تُستخدم لإنشاء Web Components. الكلاس يرث من
`LitElement`، ودالة `render()` تحدد ما يظهر في الصفحة، و`static styles` تحتوي
على تنسيق العنصر.

## ما هو Web Component؟

هو عنصر HTML مخصص نستطيع استخدامه مثل أي عنصر عادي:

```html
<catalog-app></catalog-app>
```

هذا مناسب للـMicrofrontend لأنه لا يعتمد على React أو Vue، ويمكن للـShell
تحميله كجزء مستقل.

## فائدة الملفات

| الملف | فائدته |
| --- | --- |
| `catalog-app.js` | المكون الرئيسي، التنقل، البحث، وربط الأحداث |
| `products.js` | بيانات المنتجات والفئات والحالات |
| `product-card.js` | شكل بطاقة منتج واحدة |
| `product-listing.js` | القائمة والفلاتر والترتيب والصفحات |
| `product-detail.js` | معلومات المنتج والصور والبائع والاقتراحات |
| `index.html` | نقطة تشغيل التطبيق |

## كيف يعمل التنقل؟

نستخدم الجزء الذي يبدأ بـ`#` في الرابط:

- `#/` يعرض الصفحة الرئيسية.
- `#/products` يعرض كل المنتجات.
- `#/products/1` يعرض تفاصيل المنتج رقم 1.

عند تغير الرابط، تقرأ دالة `handleHashChange()` المسار وتقرر أي صفحة تعرض.

## كيف يعمل البحث؟

النص المكتوب يُحفظ في `searchTerm`. صفحة القائمة تحول النص والحقل إلى حروف
صغيرة، ثم تستخدم `includes()` للبحث داخل اسم المنتج وفئته وحالته ووصفه.

## كيف تعمل الفلاتر؟

لكل منتج `category` و`condition`. دالة `filter()` تحتفظ فقط بالمنتجات التي
تطابق الفئة والحالة المحددتين. بعد ذلك تستخدم `sort()` لترتيب النتائج.

## كيف يتم التواصل مع الأجزاء الأخرى؟

عند الضغط على Add، لا يفتح هذا المشروع صفحة الدفع؛ لأن Cart مسؤولية عضو آخر.
بدل ذلك يرسل حدثًا اسمه:

```text
catalog:add-to-cart
```

ويحتوي الحدث على المنتج ورقمه والكمية. يستطيع الـShell أو مشروع Cart استقبال
الحدث. هذه الطريقة تقلل الترابط بين الأجزاء وتسمى **Loose Coupling**.

## أسئلة متوقعة في المناقشة

### لماذا استخدمت Lit؟

لأن دوري يتطلب Framework مختلفًا عن العضوين الآخرين، وLit مناسبة لإنشاء Web
Components مستقلة وخفيفة.

### لماذا استخدمت Material Web؟

لأن ورقة المشروع تشترط استخدام مكتبة Material Design الخاصة بالـFramework.
استخدمنا حقول النص والأزرار والأيقونات وCheckbox من `@material/web`.

### لماذا قسمت المشروع إلى Components؟

لتجنب تكرار الكود. بطاقة المنتج مستخدمة في الصفحة الرئيسية والقائمة والتفاصيل،
لذلك وضعناها في `product-card.js` مرة واحدة.

### ما معنى Shadow DOM؟

يعزل HTML وCSS الخاصين بالمكون، لذلك لا يغير CSS الخاص بالمشروع تصميم مكونات
الأعضاء الآخرين عند دمجهم.

### ما الفرق بين Props وState؟

- Property تُمرر إلى المكون، مثل المنتج الذي تستقبله بطاقة المنتج.
- State قيمة داخلية تتغير أثناء الاستخدام، مثل الصفحة الحالية وعدد السلة.

### لماذا لم تنشئ صفحة Cart كاملة؟

لأن توزيع المشروع يجعل Cart & Checkout مسؤولية عضو آخر. دوري يرسل له حدث
الإضافة فقط.

### لماذا اخترتم iframe للتكامل؟

لأنه أسهل حل لثلاثة Frameworks مختلفة ويحافظ على استقلال كل رابط. استخدمنا
`postMessage` لتمرير الأحداث إلى الـShell.

### ما أصعب جزء؟

مشاركة الأحداث والحالة بين تطبيقات مستقلة. تم حلها بتحديد أسماء وأشكال ثابتة
للرسائل بدل ربط المشاريع مباشرة ببعضها.

## ماذا تقول في العرض؟

"أنا مسؤول عن Catalog & Discovery. بنيته باستخدام Lit وMaterial Web كـWeb
Component مستقل. يحتوي على Home وProduct Listing وSearch/Filters وProduct
Detail. قسمت الواجهة إلى مكونات قابلة لإعادة الاستخدام، وأرسلت أحداثًا مثل
catalog:add-to-cart حتى يتواصل الجزء الخاص بي مع Cart بدون اعتماد مباشر عليه.
المشروع يعمل وحده ويمكن نشره على رابط مستقل ثم تحميله داخل Shell."
